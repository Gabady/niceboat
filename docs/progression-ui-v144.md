# V144 A・B 実装仕様

## A：表示と実行の一致

`src/progress144.js` の `primary` と `decision` で主操作、ラベル、許可、禁止理由、回復先を返す。状態判定は乱数・DOM・タイマー・暗黙のデータ修復を行わない。実行直前に同じ判定を使う。既存の完了済みフローだけは従来の復帰処理を通し、未読を自動消化しない。

| 状態 | 主操作 | 条件・例外 |
|---|---|---|
| ホーム | シリーズへ進む | 途中の物語があれば再開 |
| 開幕・レース間 | レース準備へ | 未完了のシリーズ |
| 練習・整備 | 出走表へ | 行動を残して進むことも可能 |
| 出走前 | 操船または観戦 | 育成中心／操船中心と最終戦条件を反映 |
| レース終了 | レース結果へ | 終了済みの走行から報酬を確定 |
| 結果 | 次走または順位確定 | 現在のレースと確定済み結果のIDが一致 |
| 節結果 | 次節または登録 | 育成終了、登録上限を反映 |
| 物語中断 | 続きを読む | 本文・選択・しおりを保持 |

ボタンには描画番号と進行対象を付与。取り外された要素だけでなく、残存する古い要素からの入力も拒否する。新しく表示したボタンから意図的に続けて練習することは可能。登録確認はコールバック実行時にも対象と条件を検証する。

結果確定などのドメイン処理は対象データのコピー上で実行し、成功後に既存オブジェクトへ反映。内部の参照を維持する。例外時は対象データを反映せず、再試行で同じ乱数から続ける。既に完了したレース走行そのものを巻き戻す機能ではない。コピー処理は進行時だけで、毎フレームの物理計算には追加しない。

対象：シリーズ開始・準備・結果確定・節終了・次走・次節・登録、会話の返答効果。ブラウザー保存の成功は別に表示し、保存失敗をゲーム処理の巻き戻しとして扱わない。保存失敗時は従来の一時保存とJSON出力を利用する。

大会・展示レースでは育成の有無や育成中の決勝条件を参照せず、そのレースで判定する。通常／短編の予選本数を区別する。

## B：準備と結果の表示

準備は目標・艇番と水面・残り行動を先に置き、練習と整備を並べ、主操作を詳細より前に置く。狭い画面では1列にする。主操作は文書の流れに置き、固定パネルで選択肢を覆わない。

レース結果は着順・賞金・予選順位・成長・獲得を先に示し、主操作の後に着順詳細と振り返りを置く。節結果も同じ順序にする。振り返りの判定内容は既存のものを使用する。

ネイティブの `details/summary` で能力・機材・育成方針と人物・行動記録・出走表・見立て・順位・着順詳細・振り返り・節記録・物語記録を開閉する。開閉11項目は `settings.details144` に保存し、取外し済み要素のtoggle通知を無視する。旧セーブはすべて閉じた状態から始める。

モーター／プロペラ、合同練習、条件付きティルト、持ち物、物語、ショップに到達できる。長押し専用の入口は作らず、説明ボタン・summaryのキーボード操作を併設する。

## 受け入れと検証の限界

- 同じ表示からの連打で練習・報酬・節進行を二重に加算しない。
- 前走のボタンや古い登録確認で現在の対象を操作しない。
- 読了・中断・再開の後に実際の育成地点へ戻る。
- 報酬・機材抽選・会話選択・履歴・登録の途中に例外を注入しても部分更新が残らず、正常化後に再試行できる。
- 開閉状態をJSON保存・読込後にも保持し、能力・乱数を変更しない。
- 全5HTMLのコード、CSS、素材を一致させ、iPhone固有補助を保持する。

`tests/progression-v144.cjs` はエンジンの故障注入15項目。通常・短編の一節テストには結果固定の状態遷移ケースを使い、物理シミュレーションとは区別する。`tests/progress-v144.cjs` は実UI関数とイベントハンドラー71項目。既存CPU・成長・走行・物語・大会の検証も再実行する。現行レポートは `*-v144.json` にまとめ、旧版の結果は今回の実績に数えない。

実ブラウザーのスクリーンショット、端末での表示やタッチ、音声、FPSは未検証。DOMアダプターの合格を実機合格としない。
