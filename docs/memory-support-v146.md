# V146 · E 物語の記憶と編集 / F 配布・診断

V145を土台にE・Fを実装。A〜Dの進行制御・準備画面・振り返り・固定挑戦を継続する。

## E：記録から後の行動へ

- ヒロイン7人の第3・5話の返答（各3択）を、第4・6話後の日常へ接続する。計42種類。元の4日常枠のうち2枠を置き換えるため、同じ節目のイベント数は増やさない。
- 相手から誘う、断る、手伝う範囲を決める、別の意見を持つ、といった行動を描く。選択肢には好感度や獲得能力の予告を追加しない。
- 本編4主題の既存の実践選択を参照し、約束のみ・実践途中・完了を区別。完了時は主題・選択別の8種の応答、未完了時は選んだ実践を確かめる導入を追加する。同じ約束の導入は一度だけ使用。回想から現在へ場面転換を挟む。
- ライバル5人の初回2択を、第4話の行動へつなぐ10種類の接続を追加する。既に作成されている第4話は変更しない。
- 参照は保存した場面の `memory146` に限定。参照元・当事者・役割・状態・参照先を保持し、ロード時に元の選択との対応を検証する。他人物へ情報を自動共有する仕組みは作らない。
- ヒロインは `memories133` と実選択の一致が必要。情報のない旧セーブには従来の汎用場面を使用し、具体的な約束を生成しない。
- 本編の新規場面と、新しく開始するヒロイン会話に `edition146` を付ける。旧版の途中会話・保存本文・返答・読書キーを維持する。本文は開始後に再生成しない。判定に実時計は使わない。
- 「前回の出来事」はタイトル、中断中の主操作、会話履歴から任意に開く。読了した本編・日常、選択済みのヒロイン・ライバルの返答を人物群別に示し、読みかけは保存されたタイトルだけを表示。未読本文・選択後の返答全文を先出ししない。開閉だけで保存・既読・しおり・報酬・乱数を変更しない。

## F：一つの入口と任意の診断

- `START.html` が遊ぶ用ZIP・全一式ZIPの共通入口。端末を粗く判別して推奨HTMLへのリンクを設定する。自動遷移やゲームデータの読み書きは行わない。代替リンクとJavaScript非対応時の案内もある。
- ゲーム内のタイトルと設定に「起動・更新ガイド」、設定と例外時の画面に「不具合の診断」を追加。詳細はモーダルと折りたたみで開く。
- 更新案内を新しい育成・育成中・登録選手・途中レースに分ける。旧版のJSON保存→新版で内容確認→復元→続きの確認の手順を記載。旧版とバックアップを確認前に削除させない。
- 自動保存はブラウザー・ファイルの場所によって分離され得ること、iPhoneのファイルプレビューには制限があることを明記する。存在しない公開URLや自動クラウド同期を案内しない。
- 診断はメモリー上のみで直近12操作・3エラーを保持。ビルド、許可済み画面名、進行段階、物語の停止状態、実際の走行規則、保存先ごとの失敗の有無・種別を集計する。
- 操作の引数、選手名、会話本文、タイトル、セーブJSON、エラーのmessage/stack、URL、ファイルパス、生のUser-Agentは出力しない。許可済み値以外は `other` / `Error` に丸める。操作・window・promise・読込エラーの型だけを記録。
- 表示内容を確認してからコピー／JSONファイル保存できる。Clipboard APIがない場合は手動コピー用に選択する。送信機能やネットワーク処理は追加しない。
- セーブ本体は別の確認画面を経て既存の書き出し処理へ進む。名前・物語履歴を含むことをそこで説明。iPhoneの共有保存補助を保持する。

## 互換性・範囲

セーブキー `kyotei_monogatari_v80` を保持。V145を既存の調整値を維持する移行対象に含める。CPU能力・スタート加速・成長・覚醒・特殊能力・ティルト・賞金・交際条件・最優秀シリーズ優勝戦の第10話解放は変更しない。短編育成は既存の一節完結のまま。

新規ネットワーク通信、外部依存、毎フレームの処理は追加しない。記憶は既存の場面数内に保存し、診断は上限つき。新規3モジュールを含め70モジュールを全5HTMLへ反映する。
